# 把已有的笔记迁进来

用户通常已经有一堆零散的东西：会话记录、实验日志、聊天里的结论、Markdown 笔记、表格。迁移的原则只有一条：**不要替用户补他没写过的东西。**

## 步骤

1. **先读，不要先写。** 把用户给的材料读完，列出：有几个课题、每个课题当前在回答什么问题、做过哪些实验、下过哪些结论、哪些结论后来被推翻。
2. **拆成四类笔记**（见 `assets/templates/`）：
   - 课题：一个要回答的问题 = 一个课题。别把"所有事"塞进一个课题。
   - 假设：材料里出现"我认为/猜想/预期"的地方。把它们写成"如果……则……，如果看到……则不成立"。**如果材料里没有反面，`converse` 留空**，让看板标出来。
   - 实验：材料里每一次跑过的东西。一种设置一条。
   - 错误：材料里出现"之前错了/更正/撤回/发现算错了"的地方，每处一条。
3. **日期用材料里的真实日期。** 不知道就写不知道（`updated` 是必填，实在没有就用文件的修改日期，并在 `status_basis` 里写"日期取自文件修改时间"）。
4. **回填的旧实验加 `backfilled: <今天的日期>`。** 没有事前预测是正常的，不要为它们编一个预测，更不要把 `predicted_at` 写成一个早于开跑的时间。看板会把它们单独标出来，提醒读者"当线索，不当结论"。
5. **配置不知道就写"待补"。** 不要猜。
6. **数字从原文复制，不要重算。** 并在笔记里写清来源（哪份文件、哪个日期）。
7. **构建，读错误，改，再构建。** 构建会一次列出所有错误。

## 常见材料的处理

| 材料 | 怎么处理 |
|---|---|
| 一份长长的实验日志 | 按实验拆成多份 `experiments/*.md`；日志本身放进 `links` |
| 会话记录（jsonl、聊天导出） | 只提取：做过什么、得到什么数字、后来改了什么。别把对话整段搬进笔记 |
| 论文阅读笔记 | 放进一个课题（如"文献调研"），`status` 多半是"无近期记录"或"搁置"，这是诚实的 |
| 一张结果表格 | 放进对应实验的"结果"，并注明口径（几个种子、什么评测集） |
| "我们之前说过 X，后来发现不对" | 进 `errors/`，并把 X 放进课题的 `retracted` |
| 一个人同时有很多课题 | 用 `lines` 分组；不要为了好看把无关课题合并 |

## 不要做的事

- 不要为了让纪律检查变干净而补写预测、判否条件或审查。警告多说明这批材料当时没按这套方法记，这本身是有用的信息。
- 不要把"进行中"当作默认状态。看材料里最后一条记录的日期，久无记录就写"无近期记录"，并在 `status_basis` 里写依据。
- 不要删旧笔记。不再进行的课题移到 `_归档/`，构建时不读，但文件保留。
- 不要把用户的私人信息（姓名、账号、服务器地址、密钥）写进会被分享的笔记。如果这个目录要给别人，先检查一遍。

## 迁完之后

运行 `python3 <skill>/scripts/build.py <目录>`，打开 `看板.html`，先看「纪律检查」页：它告诉你这批材料里哪些结论还不能当结论。然后和用户一起决定：下一个实验开跑之前，把预测写进文件。
