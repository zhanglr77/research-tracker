# 方法来由：为什么是这六条纪律

这套结构不是为了让科研"看起来有条理"。它要解决的是一个具体问题：**科研里最容易发生、也最难事后发现的错误，是把"看了结果之后的解释"当成"事先的检验"。** 下面每一条纪律都对应一种具体的、真实发生过的失败。

## 1. 预测先写

**失败**：实验做完，结果出来，回头写"其实我预期的就是这样"。这句话无法被检验，因为预期是事后构造的。

**做法**：开跑之前，把预测和"什么结果会推翻它"写进文件并存盘。`predicted_at` 早于 `started_at`。结果出来后只能追加"结果""判定""审查"。

**为什么要写判否条件**：只有预测没有判否条件，任何结果都能被解释成"符合"。判否条件把预测变成一个会输的赌注。

**一个实际的例子**：写预测时给自己的判断留一个先验概率（"我认为 A 有 55%，B 有 30%，C 有 15%"）。结果出来后你会知道自己的直觉校准得怎么样：如果你总是在 55% 的那一格里，说明你的判断力不错；如果你的"最可能"总是错，你需要少相信直觉。

## 2. 假设带反面

**失败**：假设写成"X 有帮助"，结果出来是"帮助 3%"，于是说"有帮助，只是不大"。

**做法**：每条假设写两样东西：判据（用什么口径、什么阈值）和反面（如果看到什么就不成立）。阈值要在看数据之前定。

**检验方式**：如果你写不出反面，通常说明假设还太模糊，还不能被检验。这时候该做的是把它拆细，不是去做实验。

## 3. 对照口径一致

**失败**：A 用 3 个种子，B 用 5 个种子，比较平均值，得出"B 更好"。

**做法**：比较两个实验之前，先核对配置指纹里**哪些项不同**。看板的并排对比会把不同的项高亮。如果不同的项不止一个，差异就无法归因给其中任何一个。

**配套**：报告差异时报告配对的区间，而不是两个孤立的平均值。

## 4. 错误公开登记

**失败**：发现一个数字算错了，悄悄改掉，旧结论里引用的地方不知道要改。

**做法**：写进 `errors/`，写清楚三件事：错在哪、怎么发现的、怎么处理的。同时在被影响的笔记里指向它。

**为什么这反而让人更信任你**：一个没有任何错误记录的研究，要么没有被认真检查过，要么没有被诚实地记录。错误表越具体，读者越能相信没出现在表里的部分。

**一个常见的陷阱**：错误会复发。"以后要先让脚本算数字再抄"这样的教训，写进清单之后仍然会再犯。错误登记的价值之一，是让你在第二次犯的时候能看到"这是第二次"。

## 5. 证据分级

七个等级：有数据 / 仿真 / 推断 / 未验证 / 决定 / 记录 / 想法。

**失败**：把推断写成事实；把玩具模型里的结论写成真实系统的结论；把别人转述的数字当成自己测的。

**做法**：课题的每条"已确认事实"都带一个等级。说错的要撤回并留在 `retracted` 里，**不要悄悄删**：删掉之后，别人可能还在引用它。

**关于"仿真"**：仿真结论必须写出假设，并标"只说明机理，不说明数值"。

## 6. 不凭印象

**失败**：看板显示"进展顺利"，其实只是最近没人更新。

**做法**：状态只写笔记里有记录的内容。没有记录就写"无近期记录"，这不等于没有进展，也不等于有进展。看板用最后记录日期和 `stale_days` 来提醒你"这个课题的状态已经没有依据了"。

## 一个关于"压缩"的原则

好的解释，是能用最少的结构解释全部已测数据的解释。每一轮实验结束，问自己：这一轮让理论变得更短、更能预测，还是只加了一个补丁？

如果一连几轮都在加补丁，说明方向错了，该回到结构上重新想。这不是一条能被工具检查的纪律，所以看板不检查它，但它是整套方法的目的：纪律是手段，目的是让你的理解越来越短、越来越准。

## 这套方法的限度

- 它检查的是**记录的纪律**，不是**科学的正确性**。一个守全了所有纪律的研究，仍然可能是错的。
- 预测时间戳靠自觉：你可以把 `predicted_at` 写成一个早于开跑的时间。工具能发现"写晚了的自己承认"，发现不了"谎报的时间"。`.tracker-lock.json` 能发现预测文字在首次登记之后被改，但用户随时可以删掉它。如果需要真正防篡改，把研究目录放进 git，并在开跑前提交一次。
- 看板假设研究是"课题 → 假设 → 实验"这种结构。纯理论推导、纯文献综述也能用，但会有很多字段留空。
